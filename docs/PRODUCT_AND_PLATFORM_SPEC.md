# مواصفات المنتج المرجعية — Maw3ed

**الغرض:** تعريف ما ينبغي أن يكون عليه Maw3ed كمنصة SaaS للحجز وإدارة التشغيل متعددة الأغراض، ثم مقارنة المقصود بالموجود في المستودع عبر تقارير Sam-Harness. هذه وثيقة **هدف منتج** قابلة للمراجعة، وليست ادعاءً بأن كل ميزة مدرجة مطبقة.

## 1. تعريف المنتج

Maw3ed منصة متعددة المنشآت و**متعددة الأغراض** لإدارة أي نشاط قائم على تقديم خدمة وحجزها وتشغيلها — **وليست منصة مستشفى/عيادة فقط**. العيادة والمركز الطبي قالب نشاط واحد ضمن قوالب أخرى: تعليم، مدرسة، صالون، حلاقة، تجميل، سبا، ساونا، بلياردو، ملاعب، ألعاب، لياقة، غسيل سيارات، حيوانات أليفة، فعاليات، ونشاط مخصص.

**ثلاثة نماذج حجز موحّدة (`BookingType`):**

| النموذج | الاستخدام |
| --- | --- |
| `APPOINTMENT` | موعد مع مقدم خدمة (طب، صالون، تجميل، ساونا…) |
| `RESOURCE_RENTAL` | تأجير مورد/طاولة/ملعب بالوقت الحقيقي أو لمدة |
| `BATCH_SCHEDULE` | حصة/مجموعة بسعة مقاعد (تعليم، حصص جماعية) |

التفصيل والحالات الإلزامية: [`OPERATIONAL_FLOWS_AND_STATUS_MACHINES.md`](OPERATIONAL_FLOWS_AND_STATUS_MACHINES.md).

**القيمة الأساسية:** إنشاء خدمة وربطها بالموظفين/الموارد، حجز غير متضارب (أو بسعة مقاعد)، QR وحضور، جلسات تشغيل حسب النموذج، وفاتورة نهائية للعميل — مع لوحة تشغيل عربية وتعدد منشآت.

**حدود الإصدار الأساسي المستهدف للإنتاج:** جدولة وحجز وإدارة جلسة/حضور وسجل تشغيلي عبر النماذج الثلاثة، مع عزل مستأجرين وصلاحيات وسلامة بيانات. الدفع الإلكتروني اللحظي، التسويق الآلي، والتكاملات لا تُعتبر جاهزة ما لم تُنفَّذ وتُختبر وتُوثَّق.

## 2. الجهات والأدوار

| الجهة | احتياجاتها | صلاحياتها المرجعية |
| --- | --- | --- |
| زائر/عميل/طالب/مريض | معرفة الخدمات والوقت والسعر وإتمام الحجز أو تعديله | قراءة بيانات عامة محدودة، إنشاء حجز، إدارة حجزه برمز/جلسة آمنة |
| مالك المنشأة | إعداد النشاط والخدمات والموظفين والفوترة | تحكم كامل في منشأته |
| مدير/مشرف | تشغيل المنشأة والجدول والموظفين حسب التكليف | صلاحيات مقيدة حسب المنظمة والوظيفة |
| استقبال / مكتب تشغيل | تقويم، إنشاء/تعديل الحجز، الحضور، التحصيل | عمليات محددة دون إدارة اشتراك المنصة |
| مقدم الخدمة / موظف | جدول ومواعيد وجلساته | ما يخصه فقط |
| مسؤول المنصة | دعم المنشآت والخطط | صلاحية منفصلة مع سجل تدقيق |

## 3. الرحلات الأساسية المطلوبة

### 3.1 إعداد المنشأة
إنشاء الحساب → المصادقة → workspace → اختيار قالب النشاط واللغة والمنطقة الزمنية والعملة → دعوة الفريق والأدوار → مواقع/أقسام وخدمات ومقدمو خدمة وموارد → ساعات عمل واستثناءات → سياسة إلغاء وخصوصية → تفعيل صفحة الحجز.

### 3.2 الحجز العام
اختيار الخدمة → التوفر حسب النموذج (مقدم/مورد/سعة حصة) → hold محدود → تأكيد → منع تضارب/تجاوز سعة ذري → تأكيد + بطاقة QR/رمز حضور.

### 3.3 إدارة الجلسة والحضور والفاتورة
حسب BookingType: انتقالات الحالة في وثيقة التدفقات، مع QR، تسعير نهائي، وتحصيل/فاتورة للعميل. الحالات النهائية لا تُعدَّل بصمت.

### 3.4 ربط الموظف بالفرع
`active` / `suspended` لكل مساحة عمل دون إسقاط الصلاحيات في المساحات الأخرى.

## 4. نموذج المجال المرجعي

نواة مشتركة: Workspace، Membership، Service، Staff/Provider، Resource، Customer، Booking/Enrollment، Session/Visit أو Rental Session، Hold، Payment/Invoice، Notification/Outbox، AuditEvent.

فصل `occupancy_mode` عن `composition`؛ لا تُستنتج قاعدة الحجز من اسم القالب وحده. التفاصيل: [`WORKSPACE_CAPACITY_MODEL_EDUCATION_AND_VERTICALS.md`](WORKSPACE_CAPACITY_MODEL_EDUCATION_AND_VERTICALS.md) و[`OPERATIONAL_FLOWS_AND_STATUS_MACHINES.md`](OPERATIONAL_FLOWS_AND_STATUS_MACHINES.md).

## 5. المتطلبات غير الوظيفية المستهدفة

أمن (مصادقة + عزل مستأجر + least privilege)، اعتمادية، جدولة زمنية صحيحة، خصوصية، أداء، تشغيل (CI/migrations/secrets)، وإتاحة عربية RTL.

## 6. هدف تقارير Sam-Harness

يُطلب من السرب: مراجعة خطة الإعداد والإنتاج مقابل الكود الحالي، وإصدار حزمة تقارير محدّثة (فجوات، تذاكر، خطة تنفيذ، تدقيق، مساعدة، تسويق صادق) تُستخدم لاحقاً للتنفيذ على مستودع موعد الحقيقي — دون اعتبار أي تقرير بديلاً عن الكود.

## 7. تعريف إنجاز الإصدار الأول (إنتاج محدود)

(أ) مصادقة وعضوية ودور خادمي على APIs الداخلية، (ب) لا تبديل tenant، (ج) مصدر بيانات متين مع backup، (د) الحجز/السعة حسب BookingType الثلاثة مع الحالات الموثقة، (هـ) QR/حضور ومسار فاتورة تشغيلية، (و) بريد/TLS/مراقبة موثقة حيث تُعلن جاهزة، (ز) اختبارات قبول قابلة للمراجعة.
