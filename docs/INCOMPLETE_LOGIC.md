# منطق التسعير والحجز — موعد

## أنواع تسعير الخدمة

| النوع | العرض للعميل | عند إنشاء الحجز | تثبيت السعر النهائي |
| -------- | --------------- | ------------------ | ---------------------- |
| **ثابت** | السعر | `amount = price` · `pricingStatus=fixed` | — |
| **مجاني** | مجاني | `amount = 0` · مدفوع | — |
| **نطاق** | من–إلى | عربون = `priceMin` · `pricingStatus=range_deposit` | في **جلسة الحضور** (أثناء الزيارة أو تقرير الإنهاء) ضمن `[priceMin, priceMax]` → `range_final` |
| **عند الطلب** | عند الطلب | `amount = 0` · `quote_pending` | في **جلسة الحضور** يدوياً → `quoted` |

### أين تُغلق دائرة النطاق / عند الطلب؟

ليست عند طلب الحجز العام. التسعير النهائي يتم في شاشة **حضور وتشغيل القسم** بعد فتح الجلسة:

1. قائمة الخدمات المقدَّمة تتحدّث مباشرة (أساسية + إضافات فورية).
2. يمكن تثبيت سعر بند أثناء الجلسة: `PATCH /api/ops/desk/appointments/:id/lines/:lineId/pricing`.
3. عند إنهاء الجلسة (يدوياً أو تلقائياً بعد مجموع مدد الخدمات من `checkedInAt`) يظهر **تقرير تسعير** بكل البنود؛ يجب إدخال السعر يدوياً لكل بند `range` / `on_request` غير مُنهِى.
4. `POST /api/ops/desk/appointments/:id/complete` مع `{ linePrices: [{ lineId, amount }], autoEnded? }` يرفض الإنهاء إن بقي بند يحتاج سعراً نهائياً.

API لوحة المواعيد ما زال متاحاً أيضاً: `PATCH /api/ops/appointments/:id/pricing` مع `{ amount }` (يُزامَن مع بند الخدمة الأساسية).

## أرباح المنصة

نموذج موعد الأساسي = **اشتراك SaaS** (شهري/سنوي) لصاحب النشاط، وليس عمولة وساطة على كل حجز.
عمولة الموظف/المزود داخل النشاط (إن وُجدت) خاصية Pro منفصلة وليست مصدر ربح المنصة الافتراضي.

## بنود ما زالت مفتوحة

- تحصيل عربوني/دفع إلكتروني فعلي عبر بوابة (Stripe) — التسجيل المحاسبي موجود؛ الدفع اللحظي غير موصول بعد.
- إرسال عرض السعر للعميل للموافقة عبر إشعار/رابط دفع — حالياً يُحدَّث في لوحة المواعيد / تقرير إنهاء الحضور فقط.
- إرسال بطاقة حضور QR تلقائياً عبر WhatsApp/SMS بعد الحجز (البطاقة تُعرض على صفحة التأكيد و`/pass.html`).
- RBAC صارم لمشرف القسم على مستوى الهوية (الحالي: عزل تشغيلي باختيار الفئة على شاشة الحضور).
