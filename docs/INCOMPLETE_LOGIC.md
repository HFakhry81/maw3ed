# منطق التسعير والحجز — موعد

## أنواع تسعير الخدمة

| النوع | العرض للعميل | عند إنشاء الحجز | لاحقاً من لوحة التشغيل |
|--------|---------------|------------------|-------------------------|
| **ثابت** | السعر | `amount = price` · `pricingStatus=fixed` | — |
| **مجاني** | مجاني | `amount = 0` · مدفوع | — |
| **نطاق** | من–إلى | عربون = `priceMin` · `pricingStatus=range_deposit` | تأكيد سعر نهائي ضمن النطاق → `range_final` |
| **عند الطلب** | عند الطلب | `amount = 0` · `quote_pending` | إدخال عرض سعر → `quoted` |

API تثبيت السعر: `PATCH /api/ops/appointments/:id/pricing` مع `{ amount }`.

## أرباح المنصة

نموذج موعد الأساسي = **اشتراك SaaS** (شهري/سنوي) لصاحب النشاط، وليس عمولة وساطة على كل حجز.
عمولة الموظف/المزود داخل النشاط (إن وُجدت) خاصية Pro منفصلة وليست مصدر ربح المنصة الافتراضي.

## بنود ما زالت مفتوحة

- تحصيل عربوني/دفع إلكتروني فعلي عبر بوابة (Stripe) — التسجيل المحاسبي موجود؛ الدفع اللحظي غير موصول بعد.
- إرسال عرض السعر للعميل للموافقة عبر إشعار/رابط دفع — حالياً يُحدَّث في لوحة المواعيد فقط.
