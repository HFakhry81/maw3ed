# Runbook — طلبات الخصوصية والحذف (Phase 7 قالب)

**الحالة:** قالب تشغيلي — **ليس** رأياً قانونياً ولا يغني عن مراجعة المستشار حسب السوق.

## نطاق البيانات (تشغيلي)

| فئة | أمثلة في Maw3ed | ملاحظة |
| --- | --- | --- |
| هوية حساب | بريد Clerk / مستخدم المنصة | لا تُصدَّر أسرار الجلسة |
| مساحة عمل | ملف المنشأة، الخدمات، العملاء، المواعيد | عزل tenant إلزامي |
| تشغيل | desk visits، enrollments، outbox رسائل | outbox قد يحتوي بريد المستلم وموضوعاً |
| تدقيق | workspace events / platform audit | سجلات منفصلة للمستأجر/المنصة |

**خارج الادعاء الحالي:** تصدير FHIR، محو قانوني كامل عبر UI، وبيانات قاصر/وصي قبل قرار المجال.

## مسار طلب (يدوي)

1. استلام الطلب عبر قناة معتمدة (بريد مالك المنتج / دعم) مع تحقق هوية الطالب.
2. تحديد `workspaceId` والنطاق (تصدير / تصحيح / حذف / تقييد).
3. تصدير تشغيلي محدود من أدوات موجودة فقط (PG backup مقيّد بمساحة أو JSON session) — **بدون** طباعة أسرار (`secretsPosture.redactObject`).
4. للحذف: موافقة مالك المنتج + سجل تدقيق؛ لا تحذف نسخ احتياطية خارج المضيف دون سياسة احتفاظ معتمدة.
5. ردّ على الطالب بما نُفِّذ وما بقي في النسخ الاحتياطية حسب السياسة المعتمدة.

## أوامر مساعدة (تقنية)

```bash
npm run test:phase7-ops
node scripts/retention-purge.js --policy
node scripts/retention-purge.js --dry-run
# بعد موافقة صريحة فقط:
# node scripts/retention-purge.js --apply
```

على Sam-PC للنسخ المقيّد:

```bash
MAW3ED_STORAGE=postgres DATABASE_URL=postgresql://…@127.0.0.1:5432/maw3ed \
  npm run ops:pg-backup -- --workspace=<id> --reason=privacy-export
```

## ملكية

| دور | مسؤولية |
| --- | --- |
| مالك المنتج | اعتماد الأهلية القانونية والسوق |
| تشغيل | تنفيذ التصدير/الحذف التقني وتوثيق النتيجة |
| أمن | التأكد من عدم تسرّب أسرار في المخرجات |

## حدود Phase 7

- لا واجهة عميل ذاتية الخدمة لطلبات الخصوصية بعد.
- لا تُعلن مطابقة GDPR/HIPAA أو غيرها من هذا المستند.
- أرقام الاحتفاظ التقنية في `dataRetention.js` مقترحة فقط حتى يعتمد المالك RPO/RTO.
