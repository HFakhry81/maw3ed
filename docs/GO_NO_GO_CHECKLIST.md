## شروط Go (كلها مطلوبة للنطاق المحدد)

- [ ] لا ثغرة P0/P1 مفتوحة في المصادقة / التفويض / العزل / تداخل الحجز
- [ ] بوابات Phase 8 الآلية خضراء على نفس الـ revision (`npm run test:phase-acceptance`)
- [ ] القبول اليدوي في [`PRE_LAUNCH_ACCEPTANCE_CHECKLIST.md`](PRE_LAUNCH_ACCEPTANCE_CHECKLIST.md) مكتمل للنطاق
- [ ] مصدر البيانات وmigrate/restore مفهومان؛ drill Sam-PC (5432/`maw3ed`) موقّع إن كان PG ضمن النطاق
- [ ] أسرار الإنتاج منفصلة ومراجعة؛ لا أسرار في السجلات
- [ ] المراقبة/النسخ/التصعيد معروفون (حتى لو التنبيه ما زال stub)
- [ ] صفحات الخصوصية/الشروط تتوافق مع الميزات **المفعّلة فعلياً** فقط

## ميزات تبقى No-Go حتى قرار لاحق (حاليّاً)

- Stripe live capture / تسوية مزود
- رابط دفع عرض سعر للعميل
- WhatsApp / SMS QR pass
- Hosted checkout (`hostedCheckout=false`، Whop 410)
- ادعاء جاهزية التعليم / الصالون / التأجير كمجال رأسي مكتمل
- فك قفل قالب النشاط لمسؤول المنصة (مؤجّل Phase 5)

## تنفيذ بعد Go فقط (يدوي — خارج هذا الوكيل)

1. إطلاق داخلي ببيانات اصطناعية وfeature flags للنطاق الموافق عليه فقط.
2. تجربة محدودة مع منشأة متعاونة بعد موافقة الخصوصية.
3. أي حادث خصوصية/تفويض → إيقاف التوسع فوراً.

## No-Go الافتراضي

إذا لم يوقّع المالك صراحةً **Go** على revision محدد، الحالة تبقى **No-Go**. عدم الرد ≠ موافقة.
